curl-to-csharp

Paste a curl command — including the multi-line kind Chrome/Firefox DevTools' "Copy as cURL" produces — and get working C# HttpClient code: method, headers, body, basic auth, and the -k/insecure flag all translated.

client-side only HttpRequestMessage multi-line aware
curl command
C# — HttpClient

// what gets translated

  • Method — explicit -X/--request, or inferred: POST if a body is present, otherwise GET.
  • Headers (-H) — added via request.Headers.TryAddWithoutValidation() rather than .Add(), since .Add() throws on header formats it considers invalid — generated code shouldn't crash on a header curl happily sent.
  • Body (-d / --data-raw / --data-binary, repeatable) — becomes a StringContent. Its media type comes from an explicit Content-Type header if you passed one; otherwise it defaults to application/x-www-form-urlencoded, matching curl's own default for -d.
  • Basic auth (-u user:pass) — becomes an Authorization: Basic header, base64-encoded exactly like curl does it.
  • -k / --insecure — translated faithfully to a certificate-bypassing HttpClientHandler, with a warning comment. It's exactly as dangerous in the generated code as it is on the command line.
  • -G / --get — data gets appended to the URL as a query string instead of a body, method forced to GET, matching curl's behavior.

// what doesn't

Multipart form data (-F/--form) isn't auto-converted — MultipartFormDataContent has to be built field-by-field by hand, so the tool lists the original -F arguments as a comment instead of guessing. Flags that don't affect the request itself (-v, -s, -L, --compressed, output/timeout/proxy options) are silently ignored rather than translated, since HttpClient either has no equivalent or handles the underlying behavior differently by default.

// a note on TryAddWithoutValidation

│

HttpRequestMessage.Headers only accepts request headers — content headers like Content-Type and Content-Length belong on request.Content.Headers instead, and .Add() throws InvalidOperationException if you put one in the wrong place. This tool already routes Content-Type to StringContent's constructor correctly, but if you add more headers by hand later and hit that exception, that's the mismatch to check for.
